[![MaxMSP](https://img.shields.io/badge/Max%2FMSP-8%20%7C%209-blue.svg)](https://cycling74.com)

[![Catalog](https://img.shields.io/badge/Validated%20Models-25%20Algorithms-0ea5e9.svg)]()

A peer-reference suite of **25 discrete audio DSP algorithms** implemented in Cycling '74 MaxMSP `gen~` (GenExpr), covering physical waveguide modeling, zero-delay feedback (ZDF) analog filter topologies, unitary feedback delay networks (FDN), non-linear magnetic hysteresis, strange attractors, and granular microsound synthesis.

All algorithms follow a normalized 1-to-1 naming convention (`<model>.maxpat` and `gendsp/<model>.gendsp`) and are ready for direct instantiation via `[gen~ @gen <model>]` (with `GEN-patches` in Max's Search Path), integration into `mc.gen~`, C++ export, or deployment to embedded hardware (**Electro-Smith Daisy / Oopsy**).

Key highlights of the Faust companion:
- **Bit-Accurate Verification:** Every Faust port is verified sample-by-sample against the C++ code exported directly by MaxMSP 9 (`genlib`) across 129 parameter presets (61 are identical to the bit, and the remainder agree between −191 dB and −319 dB of peak level).
- **In-Browser WebAudio Execution:** All models compile to WebAssembly and run in real time with interactive GUI sliders, signal generators, and vector SVG block diagrams generated by `faust-rs`.
- **CPU Benchmarks:** Rigorous CPU execution time comparison between `genlib` C++ and Faust C++ (Faust executing at an average 1.10x speedup).

## 🧭 Modulation & 3D Spatialization Standards

All modulation sources across the library (LFOs, chaotic attractors, stochastic random walks, and spatial multi-agent engines) adhere to a **unified Cartesian 3D spatialization norm** ($[-1, 1]$), ensuring seamless interoperability with spatial audio engines (such as **IRCAM Spat**, **Ambisonics B-format**, **Dolby Atmos**, or **VBAP 3D**) as well as standard parameter modulation:

### 1. 3D Cartesian Coordinate Standard ($[-1, 1]$)
* **$X \in [-1, 1]$ (Azimuth / Panning)**: Left ($-1.0$) to Right ($+1.0$), Center $= 0.0$.
* **$Y \in [-1, 1]$ (Elevation / Depth)**: Back ($-1.0$) to Front ($+1.0$), Center $= 0.0$.
* **$Z \in [-1, 1]$ (Height / Distance)**: Floor / Ground speakers ($-1.0$) $\leftrightarrow$ Listener Ear Level ($0.0$) $\leftrightarrow$ Ceiling / Zenith ($+1.0$).

### 2. Bidirectional Mapping: Bipolar $\leftrightarrow$ Unipolar
When driving unipolar targets (such as filter cutoffs, delay feedbacks, or VCA amplitudes in $[0, 1]$) or converting unipolar control signals to spatial coordinates, the following canonical mappings apply:
* **Bipolar to Unipolar:** $y = x \times 0.5 + 0.5 \quad ([-1, 1] \rightarrow [0, 1])$
* **Unipolar to Bipolar:** $y = x \times 2.0 - 1.0 \quad ([0, 1] \rightarrow [-1, 1])$

This normalized convention enables immediate, zero-friction routing between control generators (e.g., `lorenz-rossler-chaos`, `ufo`, `offset-spline-random`, and multi-source swarm modulators) and spatialization processors without ad-hoc scaling logic.

## 🔬 Integration & Usage

### Standalone Patcher Instantiation
```text
[gen~ @gen waveguide-string]
[gen~ @gen zdf-diode-ladder]
[mc.gen~ @chans 2 @gen cswitch-tremolo]
```

### Embedded Target Compilation (Daisy / Oopsy)
All `.gendsp` definitions follow single-sample, buffer-safe GenExpr syntax without external dependencies, compiling directly to target boards (Daisy Seed, Pod, Patch, Petal) via `oopsy`.

### C++ Source Generation
Within Max, click **Export Code** in any `gen~` inspector or dispatch `exportcode` to generate deterministic, allocation-free C++ DSP implementations suitable for VST/AU, JUCE, or embedded microcontrollers.
